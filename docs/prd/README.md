# PRD (제품 요구사항 문서)

Pin it! 기획 문서를 버전별로 모았어요. 최신 버전이 맨 위에 있어요.

PRD v0.2 이후 만들면서 바뀐 결정(장소 데이터, 지도, 하단 탭, 카테고리 관리 등)은 [DECISIONS.md](DECISIONS.md)에 모아요. 다음 PRD 버전을 쓸 때 이 목록을 반영해요.

v0.3부터는 원본 스크립트 [source/build_prd.py](source/build_prd.py)로 PDF를 만들어요. 내용을 고치면 `python docs/prd/source/build_prd.py`를 다시 실행해요.

모든 문서가 아래 7개 장으로 되어 있어요.

1. 프로젝트 소개
2. 사용자·문제·가치
3. 만들 범위 (Must·Should·Could·Won't)
4. 구조·사용 순서 (유저스토리, 화면 구조, 운영자 계정, 정상·예외 흐름)
5. 기능 설명 (완료 조건, 장소 검색 API, AI와 사람의 역할, 실패 안내, 기술·데이터)
6. 테스트 방법·성공 기준
7. 일정·담당·문제 대응 (역할, 주차별 일정, 위험 대응, 확정한 결정)

문서 안의 표시는 이런 뜻이에요: **[사실]** 출처나 실제 작업으로 확인함, **[가설]** 사용자 검증이 필요함, **[확정]** 팀 결정으로 정함, **[확인 필요]** 결정이 남음. v0.2에서는 **[v0.2]**가 이번에 바뀐 부분을 뜻해요.

## v0.2: 와이어프레임 반영본

PRD v0.1을 와이어프레임 v0.1~v0.3에서 정한 화면·문구·규칙에 맞춰 고친 버전이에요. 목표, 범위, 수치 기준, 역할은 그대로이고, 화면 구성과 계정·리스트 관리 기능이 늘었어요. 와이어프레임끼리 다른 부분은 가장 최근인 v0.3(동작하는 프로토타입)을 따라요.

**서비스 요약**

- 광고인지 드러난 리뷰와 함께 위치 핀·찜 리스트를 찾고 공유하는 모바일 웹 프로토타입이에요.
- 대상 기기는 Galaxy S26(360×780dp)이고 모바일 전용이에요.
- 첫 시장은 성수동에서 장소를 찾고 공유하는 대학생이에요. 시연용 핀 25개로 시작해요.

**기능 등급**

| 등급 | 기능 |
|---|---|
| Must | 회원가입·로그인(이메일 인증, 약관 동의·닉네임), 장소·키워드 검색, 지도와 핀 찍기, 찜 리스트, 핀 설명 작성·수정, 리뷰와 협찬·광고 표시, 공유 링크, 리스트 공개·비공개 |
| Should | 검색 리스트 탭, 리뷰 신고·자동 숨김, AI 광고성 리뷰 탐지, 리뷰 사진, 리뷰 작성 제한, 중복 핀 방지, 핀 없을 때 안내, 회원 탈퇴, 리스트 이름 바꾸기·삭제·핀 빼기 |
| Could | 카테고리 칩, 근처 핀 합치기 제안, 도움돼요·찜 수, 핀 미리보기 카드, 내 위치, 최근·추천 검색어, 내 활동, 닉네임 수정·비밀번호 변경 메일 |
| Won't | 실시간 공동 편집, 방문 인증, AI 장소 추천, 팔로우·좋아요, 여러 지역, 소셜 로그인, 핀 신고 |

**주요 수치 기준**

- 비밀번호 8자 이상(영문·숫자), 닉네임 2~12자, 인증 메일 재발송 60초에 한 번
- 핀 이름 30자, 설명 500자, 리뷰 1~1000자, 리스트 이름 20자
- 근처 장소는 300m 안에서 최대 4개, 30m 안에 다른 핀이 있으면 안내
- 리뷰 사진 최대 3장·장당 5MB, 신고 3건이면 자동 숨김, 가입 7일 이내 계정은 하루 리뷰 3개
- AI 탐지는 테스트 리뷰 60개에서 정확도 80% 이상

**화면:** S-00 시작부터 S-14 리뷰 검토까지 16개 화면과 신고·찜하기 바텀시트예요. 하단 탭은 홈·리스트·검색·내 정보 4개예요.

**데이터:** profiles, pins, reviews, review_photos, review_reports, review_ai_checks, lists, list_pins 8개 테이블이에요. 모든 테이블에 RLS(행 단위 접근 규칙)를 켜요.

**테스트:** 기능 시나리오 26건(T01~T26)을 각 3번 실행해서 실패 0번이 목표예요. 사용자 테스트는 학생 5명이에요.

**v0.1 대비 바뀐 점**

| 영역 | v0.1 | v0.2 |
|---|---|---|
| 화면 수 | 14개 + 신고 바텀시트 | 시작 화면(S-00)을 더해 16개 + 예외 상태 화면 |
| 회원가입 | 이메일·비밀번호 1단계 | 약관 동의 → 정보 입력 → 이메일 인증 3단계 |
| 닉네임 | 없음 | 가입 때 입력, 리뷰·공개 리스트에 이메일 대신 표시 |
| 약관 동의 | 없음 | 필수 4개(만 14세·이용약관·개인정보·리뷰 작성 원칙), 선택 1개(위치 정보) |
| 내 정보(S-03) | 이메일 확인·로그아웃 | 닉네임 수정, 활동 수, 신규 계정 제한 현황, 위치 정보 토글, 내 활동, 약관, 회원 탈퇴 |
| 공통 탐색 | 지도 홈의 내 찜 리스트 바로가기 | 하단 탭 4개 (홈·리스트·검색·내 정보) |
| 지도 홈(S-04) | 핀 지도·검색창·핀 찍기 | 카테고리 칩, 핀 미리보기 카드, 내 위치 버튼, 핀 종류별 색 |
| 검색(S-05) | 결과 목록·지도 | 입력 중 상태(최근·추천 검색어), 탭별 결과 수, 결과에 리뷰·찜 수 |
| 핀 찍기(S-06) | 길게 눌러 위치 지정 | 눌러서 지정 + 끌어서 옮기기, 카테고리 필수, 근처 장소 300m 목록 |
| 찜하기(S-11) | 별도 화면 | 핀 상세 위 바텀시트, 시트 안에서 새 리스트 만들기 |
| 리스트 관리(S-12) | 공개 전환·링크 복사 | 이름 바꾸기, 삭제, 핀 빼기(되돌리기), 비공개 전환 확인 |
| 리뷰 검토(S-14) | 대기열·처리 3종 | AI 의심·신고 누적·미판정 탭, 처리 되돌리기 |
| 대상 기기 | 정하지 않음 | Galaxy S26, 360×780dp, 모바일 전용 |
| 데이터 | 테이블 7개 | profiles 추가, 글자 수 제한, 리스트 updated_at 추가 |
| 테스트 | 시나리오 20건 | 계정·리스트 관리 6건(T21~T26) 추가 |

**아직 정할 것 (7-5)**

- 리뷰 수정을 허용할지, 허용하면 수정한 리뷰도 AI가 다시 판정할지
- 회원 탈퇴 뒤 핀·리뷰를 지울지, 작성자를 "알 수 없음"으로 남길지
- 시작 화면(S-00)을 유지할지 (지금 프로토타입은 바로 지도 홈으로 들어가요)
- 카테고리 "기타"를 지도 홈 칩에도 넣을지
- 새 기능 등급(회원 탈퇴·리스트 관리는 Should, 미리보기 카드·내 위치·검색어·내 활동은 Could)이 맞는지
- 핀 위치 지정 방식은 v0.3의 "누르기 + 끌기"를 따랐어요

## v0.1: 확정본

이전 초안에서 **[팀 결정 필요]**로 남겨 둔 16건을 모두 정하고 역할 분담을 확정한 문서예요. 결정 목록은 7-4에 모여 있어요. 파일 표지에는 "v1.0"으로 적혀 있지만, 저장소 폴더 이름에 맞춰 v0.1로 불러요.

**서비스 정의**

- **유형:** 모델 구현형. AI 광고성 리뷰 탐지를 직접 연결해 작동하게 만들어요.
- **한 줄 설명:** 장소·키워드로 핀과 리스트를 검색하고, 광고인지 표시된 리뷰를 함께 보는 위치 공유 웹 프로토타입이에요.
- **목표 사용자(가설):** 여행·맛집·산책 장소를 찾고 친구와 공유하는 20~30대
- **풀려는 문제(가설):** ① 돈을 받고 쓴 후기를 구분하기 어려워요. ② 기존 지도 앱은 가게 단위로 저장해서 뷰 포인트·산책길 같은 위치를 남기기 어려워요.
- **차별성(가설):** ① 가게가 아닌 위치에도 남기는 공개 핀 ② 리뷰마다 협찬·광고 표시와 신고 ③ 검색 결과 리스트 탭에서 공개 리스트 검색

**근거로 쓴 사실**

- 공정위가 2024년 SNS를 점검해 뒷광고 의심 글 22,011건을 적발했어요(2025년 3월 발표).
- 「추천·보증 등에 관한 표시·광고 심사지침」 개정(2024년 12월 1일 시행)으로 글 중심 매체는 대가 표시를 제목이나 첫 부분에 넣어야 해요. → 리뷰 맨 위 "협찬·광고" 고정 표시의 기준
- 개인정보위가 2022년 카카오맵 즐겨찾기 개선을 권고했어요. 당시 계정의 약 85%가 공개였어요. → 리스트 기본값을 비공개로 정한 근거

**확정한 결정 (16건 중 주요 항목)**
